# OpenLearn — Universal LMS

A simple public learning library built with Next.js, TypeScript, and Supabase. It supports public courses, lessons, YouTube embeds, direct video files, Dropbox resource links, Supabase Storage links, external materials, and file uploads.

## Requirements
- Node.js 18.17+ (Node 20 LTS recommended)
- A Supabase project

## Run locally

```bash
npm install
cp .env.example .env.local
```

Fill `.env.local` with the Supabase project URL and anon key. Set `NEXT_PUBLIC_ADMIN_EMAILS` to one or more comma-separated admin email addresses.

1. In Supabase, open **SQL Editor** and run `supabase/schema.sql`.
2. In Supabase **Authentication → Users**, create an account for your admin email. Set a password.
3. Make sure the same email appears in `NEXT_PUBLIC_ADMIN_EMAILS`.
4. In Supabase Authentication → Users, copy that admin user's UUID. In SQL Editor, run `insert into public.admin_users(user_id) values ('YOUR-USER-UUID');` using the actual UUID. This database role is what enforces write access.
5. Run the app:

```bash
npm run dev
```

Visit `http://localhost:3000`. Public users can browse published courses without logging in. Admins use **Creator studio** to sign in and publish courses.

## Supported resources
- **YouTube:** recognized and embedded with a privacy-enhanced YouTube embed.
- **Direct video files:** `.mp4`, `.webm`, `.ogg`, `.m4v`, and `.mov` use the native browser video player if the host permits playback.
- **Dropbox:** recognized as a Dropbox link; opens externally because shared-link permissions and browser embedding vary.
- **Supabase Storage:** public URLs open as external resources; private buckets need signed URLs generated by a trusted server/API and are not made public by this app.
- **Other links:** shown as an external resource with an open-link fallback.
- **Materials:** external URLs or uploaded files; uploads go to the `materials` public bucket (50 MB maximum by default).

## Important security notes
- Public courses and files are intentionally public. Do not upload sensitive or licensed content without permission.
- `NEXT_PUBLIC_ADMIN_EMAILS` is a UI gate only. Database writes are additionally restricted by the `public.admin_users` table in RLS. Add only trusted user UUIDs to that table. Keep the public anon key in the browser; never expose a service-role key.
- Uploaded materials are publicly downloadable by design. Use a private bucket and authenticated server-generated signed URLs if some course files should remain private.
- The LMS does not bypass a provider's restrictions, DRM, or access controls. Downloads only work when the source owner/provider permits them.
- If a lesson contains a private Supabase Storage object, use a signed URL produced server-side; never expose a service-role key in the browser.

## Project structure

```text
app/
  page.tsx                Public course library
  course/[id]/page.tsx    Lesson player and materials
  admin/page.tsx          Course creator and upload form
  globals.css             Responsive styling
lib/
  resources.ts            URL/resource detection
  supabase.ts             Supabase browser client
  types.ts                Course types
supabase/schema.sql       Database, RLS, storage setup
```
